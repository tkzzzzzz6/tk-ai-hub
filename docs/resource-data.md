# 资源数据与程序分离

## 目录

| 文件或模块 | 职责 |
| --- | --- |
| `data/resources.json` | 初始资源：完整中英文正文、分类、标签、来源、效果图/视频 URL |
| `data/catalog-imports.json` | 站长批准的导入批次：稳定 key、资源 ID、初始状态 |
| `data/site.json` | 网站资源类型和社交链接 |
| `data/skill-packages.json` | Skills 下载包与固定版本信息 |
| `lib/resource-schema.ts` | 文件数据与管理员 API 共用的格式校验 |
| `lib/resource-catalog.ts` | 导入 JSON、检查 ID 和批次引用 |
| `lib/resource-bootstrap.ts` | 将站长批准的数据一次性写入数据库 |
| `lib/store.ts` | 读取线上数据库、映射资源，不嵌入资源正文 |
| `lib/prompt-template.ts` | 纯函数：识别参数、生成复制标记 |
| `app/prompt-content.tsx` | 展示参数和高亮正文，不写数据库 |
| `lib/resource-export.ts` | 明确的公开资源导出字段 |

页面从服务器取得数据库中的公开资源，再由组件渲染。文件提供可移植的初始资料；线上管理员新增、修改、隐藏和删除的结果保存在 D1 数据库。部署不会用文件覆盖已经修改的线上内容，也不会把已隐藏/删除的资源重新公开。

## 增加初始资料

1. 在 `data/resources.json` 数组中增加一条完整资源，可同时提供 `content` / `contentEn`、`title` / `titleEn`、`description` / `descriptionEn`。
2. 使用稳定、唯一的 `id`；`category` 为 `提示词`、`Skills` 或 `MCP`。用途 `topic` 应采用现有分类。
3. 效果图使用 `demoUrl`，类型设 `image`；直链视频设 `video`，平台页面设 `auto` 或 `link`。来源 URL 与效果展示 URL 是两个字段。
4. 在 `data/catalog-imports.json` 增加一个唯一批次 key，并引用新增 ID。通常 `status` 设 `pending`，由管理员审核；只有站长明确批准公开的初始资料才设 `published`。
5. 发布时由通用导入器处理，通常不需要修改页面或导入器代码。

旧批次 key 是已执行记录，不要修改它来重新导入已有资料。文件修改不自动更新现有 ID；线上更新应使用管理员编辑与修订机制。该规则保护管理员后来作出的修改。

## 可替换内容

支持两种正文写法：

```text
{argument name="角色列表" default="角色A / 角色B / 角色C / 角色D"}
{{角色列表：角色A / 角色B / 角色C / 角色D}}
```

阅读时用蓝色标记突出显示，并展示名称与默认示例。复制时统一为 `{{角色列表：角色A / 角色B / 角色C / 角色D}}`；用户替换整个标记为具体角色列表即可。英文正文独立保存英文参数名称与默认值。没有表单输入或自动执行步骤。

数据库和 JSON 导出保留原始正文，复制格式转换仅发生在复制模块中。原始参数语法不会丢失，也不会被 i18n 当作插值执行。无效或不完整的参数原样保留，不会吞掉正文。

## 导出与复用

- 页脚「导出公开资源 JSON」下载当前数据库中的所有公开资料。
- 详情页「导出 JSON」只下载当前资料。
- 公共接口：`GET /api/resources/export`；单条接口加 `?id=资源ID`。
- 导出是 JSON 数组，可作为其他项目的数据输入，也可粘贴进管理页的「导入 GPT 整理结果」（每次最多 10 条，更多资料分批导入）。导入到本站时会进入候选列表，需要审核；导出中的 ID、状态和修订号不会赋予公开权限。
- 仅导出公开字段；不会包含游客投稿、用户、收藏、管理员信息或编辑历史。

复制源码中的 JSON 并不能代替线上数据备份。应定期导出当前公开资料；需要完整后台备份时再单独备份数据库。
